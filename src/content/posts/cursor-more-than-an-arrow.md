今天在看一个网页时，把鼠标移到一段纯文字上，下意识停顿了一下。

鼠标指针从原本默认的小箭头，变成了一个工字形的竖条。只要是经常用电脑的人，看到这个形态就会产生肌肉记忆：**这里的文字可以被选中或者框选。**

天天对着浏览器，我们可能很少去琢磨这根小竖条。借着这个契机翻了翻规范和背景，发现围绕光标和文本交互，有几个挺有意思的细节。

## 这根“工字钢”叫什么？

这个工字形光标的正式名字叫 **I-beam**（工字钢）。

它的造型确实来自于工业时代的打字机——打字机内部用来引导字模活动的导槽截面就是一个工字形。70 年代施乐帕罗奥多研究中心（Xerox PARC）在研发图形用户界面（GUI）时，借用了这个机械形状来代表“文字编辑与可选区域”。

后来苹果和微软的系统全盘沿用了这一隐喻。如今几十年过去，机械打字机早已退出主流，但这个符号依然稳稳停留在所有操作系统的屏幕上。

## 默认行为与语义提示

在浏览器里，即使你没有写任何 CSS，把鼠标划过一段普通文本时，光标也会默认切成 `cursor: text`。

这是浏览器底层的默认语义规范：它在无声地告诉用户，这段内容处于就绪状态，可以复制、可以划词高亮。

除了最常见的 `pointer`（小手）和 `text`（I-beam），CSS 的 `cursor` 属性其实提供了一整套标准状态提示：

```css
cursor: grab;        /* 张开手掌：提示元素可以被拖拽（如地图、画板） */
cursor: grabbing;    /* 握紧手掌：正在拖拽中 */
cursor: not-allowed; /* 禁止标识：不可操作/禁用状态 */
cursor: col-resize;  /* 左右双箭头：可以调整表格列宽 */
cursor: crosshair;   /* 十字准星：常用于截图、取色或画布标注 */
```

不需要额外弹出文字说明，鼠标形态的细微切换本身就是成本最低的交互反馈。

## 几个容易关联到的文本交互属性

平时与光标常常搭配出现的，还有另外几个控制层面的属性：

### 1. 能打字，但不属于表单：contenteditable

有时在网页上不仅能看到 I-beam，点一下还会出现一闪一闪的文字插入符（Caret），甚至能直接敲字进去，但查看源码却发现它并不是 `<input>` 或 `<textarea>`。

这就是 `contenteditable`：

```html
<div contenteditable="true">你可以直接修改这段文字</div>
```

像 Notion、飞书文档这类富文本编辑器，正文编辑区很大程度就是基于可编辑节点搭建的，比原生文本框在排版和节点嵌套上自由得多。

### 2. 看得见，但划不动：user-select

```css
user-select: none;
```

如果给文字加上这一行，鼠标悬停时通常不再显示 I-beam，文字也无法被高亮选中。

常用于两类场景：一是按钮、菜单等纯操作性 UI，防止用户频繁双击时意外选中文本产生蓝色高亮块；二是一些版权保护站点的防拷贝手段。当然，后者防不住开发者工具，F12 打开 DOM 节点该是什么还是什么。

### 3. 点击穿透：pointer-events

```css
pointer-events: none;
```

当一个浮层或者图标盖在文字上方、但又不想遮挡下层点击与划词动作时，这个属性最有用。它让当前元素在交互层面变成“空气”，光标会直接穿透它与下一层的 DOM 交互。

## 总结

光标大概是界面里存在感最弱、但使用频次最高的元素。好的交互往往让人注意不到它的存在——如果什么时候光标该变小手时没变、该选文字时卡住，那种顿挫感才会立刻暴露出来。熟悉这套默认规则，在自己做界面时少制造点别扭，就算没白了解。
